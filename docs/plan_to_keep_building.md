## 1. Concrete Protocol: How to Add the Next Case Study

To maintain momentum and prevent portfolio stagnation, new engineering projects are published using the standardized **Week 2 Three-Beat Shape**. Each new case study takes less than 30 minutes to document and deploy.

### Where the Next Case Study Goes
* **Markdown Artifact:** `docs/case-studies/02-realtime-kafka-telemetry.md` inside this GitHub repository.
* **Portfolio Showcase:** A new project card added to `index.html` on [pervaiz-ahmed-ml.netlify.app](https://pervaiz-ahmed-ml.netlify.app/).

### The 3-Beat Publishing Steps
1. **Beat 1: The Problem (Context & Friction)**
   * Document the specific data volume, structural bottleneck, or latency issue.
   * *Example:* "Batch inferences on 79M historical search logs had a 4-hour delay, making live algorithm update detection impossible."
2. **Beat 2: What I Did (Technical Execution)**
   * List the exact tech stack, feature engineering, and leakage prevention steps.
   * *Example:* "Built an asynchronous Python Kafka consumer stream paired with a microsecond-latency LightGBM inference service."
3. **Beat 3: What Came of It (Measurable Impact)**
   * State the final quantitative metric, benchmark comparison, and live links.
   * *Example:* "Reduced inference delay from 4 hours to < 12ms per event with 0.880 ROC-AUC score."
